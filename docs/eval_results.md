# Evaluation results

`make eval` runs everything in the order the brief requires, on a fresh temporary database:

1. index `data/sops` and ask the 15 questions in `eval_questions.csv`, each as its `asked_as_role`;
2. warm the cache with the two front-desk questions whose answers are about to change (walk-in %, refund limit);
3. re-index with `data/sop_updates/2026-11-01`, then run the same re-index again to check it is idempotent;
4. ask the 8 questions in `eval_questions_after_update.csv` as their roles;
5. run the 5 inputs in `pii_test_inputs.csv` through the same service.

Per-provider outputs, generated by the script and not edited:
- [`eval_results_fake.md`](eval_results_fake.md): offline, deterministic (extractive stub + hashed bag-of-words embeddings)
- `eval_results_gemini.md`: produced by `make eval-gemini`, which needs a `GEMINI_API_KEY` (see "Status" below)

## What "pass" means

Criteria are in [`eval/criteria.py`](../eval/criteria.py) and were written from the expected answers before looking at model output.

| Question type | Pass when |
| --- | --- |
| Answerable (Q01 to Q10) | status `answered`, cites the expected SOP, and contains every "must" fact, i.e. the number or rule a staff member acts on (e.g. Q01: 2 hours, OH-05, soap/running water, 6 weeks). Wording is not judged. |
| Unanswerable (Q11 to Q13) | status `not_found` and no citations |
| Conflict (Q14, Q15) | cites **both** SOPs and states both rules (2 h and 24 h; twice and once daily). Whether the `conflict` flag is set and the stricter rule recommended is reported separately as a quality metric. |
| After update (U01 to U08) | as above, plus freshness: the superseded value must be absent (U01 not 20%, U02 not Rs 1,000), citations carry the new version, SOP-11 v1.2 is absent from the context and no conflict is reported (U03), the withdrawn SOP-15 is absent from answer and context (U04), the HR-only SOP-17 never reaches a nurse's context (U06), and SOP-05 sections are not duplicated after the rename (U08) |
| Every question | **governance invariants:** every chunk in the LLM context is readable by the asking role and belongs to a currently published version |
| PII | flagged exactly when the pack says "flag" |

### Notes on the failures

All four failures are answer-wording failures of the **extractive stub**. In every case the correct SOP was already in the context, and no freshness, access or refusal check failed.

- **Q01** (needle-stick procedure): the stub picks the excerpt with the most question words, SOP-11 section 2 ("including ... needle-stick injuries"), so the procedure from SOP-04 sections 2 to 5 is missing even though all of SOP-04 was in the context.
- **Q04** (fridge at 10 degrees): vocabulary mismatch. The question says "fridge", the SOP says "refrigerator" and "2 to 8 degrees Celsius". Lexical overlap stays under the stub's 50% threshold, so it answers `not_found`. A wrong refusal is the safe failure direction.
- **U01** (walk-in %): picks SOP-02 section 4 (late arrivals and walk-in queue) instead of section 3, so "25%" is missing. Nothing stale: the citation is v2.4 and "20%" never appears.
- **U05** (smoke): picks SOP-16 section 1 (purpose) instead of section 2 (R.A.C.E.).

The conflict *flag* and *stricter-rule recommendation* are 0/2 offline by construction: the stub never sets the flag. These need the real model.

## Status of the Gemini run

The Gemini adapter is implemented and contract-tested with a mocked transport, but the environment this was built in could not reach Google's API. **Before submitting:** put a key in `.env` and run `make eval-gemini`. That writes `docs/eval_results_gemini.md` and `eval/results_gemini.json`, including the top retrieval score for each question. Use those scores to set `MIN_RETRIEVAL_SCORE`: just below the lowest score of an answerable question, as long as that stays above the unanswerable ones. Then add the numbers to the table in the README.

Things to look at in that run:
- Q12 (amoxicillin dose): the model must refuse even though SOP-09 (dispensing) is retrieved. The prompt forbids general knowledge, and an answer without a valid citation is converted to a refusal in code.
- Q14 / Q15: whether `conflict` is set and the stricter rule recommended.
- U03: whether the model reports a conflict that no longer exists. It should not, because SOP-11 v2.0 now defers to SOP-04.
